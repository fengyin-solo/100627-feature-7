# 水电站机组运行检修管理平台

面向电站台账、机组运行、调速励磁、主变与闸门、大坝渗流位移监测、机组检修与发电计划的一体化水电站运行检修管理平台。

这是一个**纯前端**管理平台：Vue 3 + Vite + TypeScript，仓库里没有后端服务。业务数据由
`frontend/src/data/` 下的本地数据层提供：首次打开用示例数据播种，之后的登记、筛选与状态流转
结果都持久化在浏览器 `localStorage` 里，刷新或重开浏览器都还在。dev server 已关掉自动打开页面，
启动后按终端打印的地址手工打开。

## 目录结构

```text
.
├── frontend/                 Vue 3 + Vite + TypeScript 前端（唯一运行单元）
│   ├── src/views/            每个业务模块一个页面
│   ├── src/api/local-service.ts   本地数据服务：列表、筛选、动作流转、导出
│   ├── src/data/             模块元数据 / 示例数据 / localStorage 持久化
│   ├── src/stores/           会话与筛选状态
│   └── vite.config.ts        dev server 配置（open: false，无 /api 代理）
├── .gitignore
└── docker-compose.yml
```

## 启动

```bash
cd frontend
npm install
npm run dev
```

前端默认监听 `http://127.0.0.1:5173/`，dev server 不会自动打开浏览器，需要自己访问。

生产构建：

```bash
cd frontend
npm run build
```

## 业务规则

### 机组状态链（机组运行）

机组状态只沿一条链推进，跳步操作一律退回，并在提示里指出当前停在哪一步、该从哪几步走：

```text
待启动 ──开机并网──▶ 运行中 ──停机转备──▶ 停机备用 ──转待启动──▶ 待启动
                     │
                     └──登记故障──▶ 故障停机 ──检修闭环（工作票办理完工）──▶ 停机备用
```

- 开机并网只能从「待启动」走；停机转备只允许从「运行中」进入；登记故障允许从「运行中」「停机备用」登记。
- 「转待启动」是本次补的裁决：备用机组要再次并网，必须先回到待启动，否则「开机并网只能从待启动走」会把备用机组卡死。
- 故障停机回到停机备用**没有直接动作**，唯一通道是检修工作票走完「待审批 → 已批准 → 检修中 → 已完工」。

### 联动口径（三处读同一份数据）

机组运行页、发电计划页、检修工作票读的是同一份机组数据（`local-service.ts` 的 `fleetSnapshot()`）：

- **可调出力** = 运行中 + 停机备用机组的有功出力合计；故障停机、待启动机组一律不计入。机组还在故障停机时，发电计划里看不到它的出力。
- **开工资格**：检修工作票「开工检修」要求检修机组已停机（停机备用或故障停机）；运行中、待启动的机组一律退回。检修页的「检修机组」列会直接标注机组当前状态，不会出现两种口径。
- 登记故障会自动：① 在设备缺陷清单落一条「待处理」缺陷（来源 = 机组运行-登记故障）；② 开立一张「待审批」检修工作票，让检修闭环有票可走。缺陷处置页这个入口同样能看到。

### 幂等与累计

- 同一台机组连续两次开机并网只生效一次：第二次幂等放行但不重复变更，运行台数不多出。
- 累计运行小时按并网时刻累加：停机转备（或运行中登记故障）时结算「当前 − 最近并网时刻」；停机之后不再跳数，没有后台计时。
- 重复登记缺陷只认第一次的取值，先入库的那份保留；备件领用重复提交只扣一次数量，库存为 0 不许再领。

### 缺陷处置

待处理 → 处理中 → 已消除 单向流转，已消除即归档（不再计入待处理）；待处理/处理中可以登记挂账。归档后的缺陷不能再派发、不能挂账。

### 历史数据与旧数据兼容（裁决说明）

- 存储结构升到了 `STORAGE_VERSION = 2`：旧版 localStorage 数据首次读取时原地迁移一次并写回，历史记录不清空、状态文本不改写。
- **早期只记了运行状态的机组**，起停时刻按这条规则补：运行中的补记「最近并网时刻 = 迁移时间」；停机备用/故障停机的补记「最近停机时刻 = 迁移时间」；待启动机组本就无起停记录，不补。所有补记都在「数据来源」列写明「迁移回填：…」，历史台账按机组编号顺序补录。
- 累计运行小时缺项或原值无法识别的按 0 起算，来源里写清；是数字的一律保留。
- **既有缺陷等级不改写**：历史数据里等级填成什么都原样保留（那是当时的结论），只有新登记的缺陷用规范等级；老缺陷迁移时只补「来源 = 历史台账」。
- 老检修票的「检修机组」对不上机组编号的，视为未关联机组：开工资格无法核对机组口径，按既有单据流程放行，页面上会标注「未关联机组」。
- 每个模块最后一列「××状态」与内部 status 强制同步成一份，杜绝两种口径。

### 概览与列表一致性

待处理 = 不在 `settledStatuses` 里的状态；异常 = 状态名含「故障/异常/报警/超限/告警/损坏/停工/偏高」。这套推导在 `src/data/rules.ts` 里只有一份，概览页、列表页、迁移结果都从这里出，条数必然对得上。

## 约定

- 每个模块的页面在 `frontend/src/views/<模块>/index.vue`，页面只负责渲染，读写统一走
  `frontend/src/api/local-service.ts`。
- 字段、状态、动作、流转目标与办结状态集中在 `frontend/src/data/modules.ts`；示例数据在
  `frontend/src/data/seed.ts`。
- 状态流转只允许在 `local-service.ts` 里改，页面组件不做业务判断；动作的允许来源状态在
  `modules.ts` 的 `actionSources` 里声明，缺省按状态表顺序取目标前一格。
- 待处理/异常/状态列同步的推导在 `frontend/src/data/rules.ts`；旧数据迁移在
  `frontend/src/data/migrate.ts`。
- 业务规则有一条可执行的验证：`npm run verify:logic`（58 项断言，覆盖状态链、幂等、
  检修闭环、缺陷联动、备件扣减、口径一致与迁移）。
- 想回到初始数据：清掉浏览器里 `hydropower-plant-om:entries` 这一项，或调用 `resetModule(模块)`。
